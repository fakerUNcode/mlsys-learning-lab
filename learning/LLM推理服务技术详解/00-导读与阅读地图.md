# LLM 推理服务技术详解：从显存到延迟的完整推导

> **本文目标**：让一个刚入门的人读完能回答三个问题——**这是在干什么？为什么要这么干？这么干为什么起作用？**
> 全文每一处推导都从最少的几个前置概念出发，不跳步；每个等号右侧都标注了依据。

## 阅读地图

> 推理服务全景图曾使用带临时签名的外部链接，签名已从仓库中移除；章节依赖和主线见下表及下文。

**一句话主线**：

```
显存（地基） → 决定并发数 → 决定排队长度 → 决定 TTFT
                    ↓
              显存耗尽 → 抢占 → 尾部延迟恶化（P99）
                    ↓
              "踢谁"由公平性策略决定

Prefill（吃算力） / Decode（吃带宽） 的物理差异
       → 产生全部调度复杂性
       → 决定 TTFT 与 TPOT 能否被独立优化

目标函数：在满足 TTFT/TPOT 的 SLO 前提下，最大化吞吐（tokens/s）
```
