# 一、名词地基

这一章不推导，只把后面反复出现的词一次性讲清楚。**如果你已经熟读前文对话，可跳过。**

## 1.1 Token

模型处理文本的**最小单位**。它不等于"字"：

- 中文大约 1 个字 ≈ 1~2 个 token
- 英文大约 1 个单词 ≈ 1~3 个 token

所有计费、限速、长度限制，底层都按 token 算，不按字符。

## 1.2 自回归生成（Autoregressive）

**模型一次只能吐出一个 token，且必须一个接一个来，无法并行。**

原因是 Transformer 使用**因果注意力（Causal Attention）**：生成第 $N$ 个位置时，只许它"看见"前 $1 \sim N-1$ 个位置，不许偷看后面。所以第 10 个字必须等第 9 个字确定后才能算。

> 这就是为什么"生成 500 字"必然比"生成 50 字"慢 10 倍——不是写得慢，是**物理上必须串行**。

## 1.3 Attention 与 Q / K / V

每个 token 进入模型后生成三个向量：

| 符号 | 全称 | 作用 |
|---|---|---|
| **Q** | Query（查询） | "我现在想找什么样的信息" |
| **K** | Key（键） | "我是什么标签，供别人来匹配" |
| **V** | Value（值） | "我实际携带的内容" |

新 token 拿自己的 **Q** 去和前面所有 token 的 **K** 算相似度（点积），得出"我该关注谁多一点"，再按这个权重把对应的 **V** 加权求和——这就是"结合上下文理解当前位置"。

##  先扫清六个词

| 词             | 大白话                                                       |
| -------------- | ------------------------------------------------------------ |
| **向量**       | 一串有序的数字，比如 `[0.3, -1.2, 0.7]`。可以理解成"用几个数字描述一个东西" |
| **矩阵**       | 一个数字表格，有行有列，比如 3 行 128 列                     |
| **维度**       | 这串数字有几个数。3 个数就是 3 维；4096 个数就是 4096 维     |
| **token**      | 模型处理文本的最小单位。大致理解成"一个字"或"半个词"就行     |
| **点积**       | 两串**等长**的数字，逐位相乘再全部加起来，最后得到**一个**数。这个数越大，说明两串数字越"同向、越像"。所以它常被当作"相似度打分" |
| **权重矩阵 W** | 一张固定的数字表，是模型训练出来的参数。所谓"训练模型"，本质就是反复调这些数字，调到好用为止 |

补充一句贯穿全文的关系：**一个数字表（矩阵）乘以一串数字（向量），得到的还是一串数字（向量）**。这就是下面反复出现的"投影"——说白了就是"乘个矩阵，把一串数字变成另一串数字"。

##  Q / K / V：其实有三层东西都叫这个名字

**核心结论：参数是矩阵（全模型共享），token 产出的是向量（每个 token 一份），把所有 token 的向量摞起来，才叫 Q/K/V 矩阵。**

| 层级                | 是什么                               | 形状                     | 归谁所有                         |
| ------------------- | ------------------------------------ | ------------------------ | -------------------------------- |
| ① `W_Q / W_K / W_V` | 三张训练出来的**参数表**（权重矩阵） | `d_model × d_head`       | **全模型共享**，不属于任何 token |
| ② `q_i / k_i / v_i` | 第 i 个 token 投影后得到的**向量**   | 长度 `d_head` 的一串数字 | 每个 token 各一份                |
| ③ `Q / K / V`       | 所有 token 的向量摞成的**矩阵**      | `n × d_head`             | 每个 token 只占其中**一行**      |

> `n` = 这句话里 token 的个数；`d_model` = 模型内部用来描述一个 token 的数字个数（比如 4096）；`d_head` 见第 3 节。

公式（括号里标了形状）：

```
x_i          第 i 个 token 在模型内部的表示（1 行 × d_model 列），
             可以理解成"这个词现在的含义档案"
q_i = x_i · W_Q      → 1 行 × d_head 列
k_i = x_i · W_K      → 1 行 × d_head 列
v_i = x_i · W_V      → 1 行 × d_head 列

X            整句话所有 token 的表示摞起来（n 行 × d_model 列）
Q = X · W_Q          → n 行 × d_head 列
K = X · W_K
V = X · W_V
```

**所以"一个 token 对应一个矩阵"是错的，它只对应矩阵里的一行。**

## 注意力到底在算什么：四步走

假设当前这句话有 3 个 token，我们看第 3 个 token 怎么"结合上下文"。

### 第 1 步：打分 —— 当前词跟前面每个词有多相关

拿当前 token 的 `q`（查询：我在找什么），去和所有 token 的 `k`（标签：我这里有什么）做点积：

```
分数 = q · k₁,  q · k₂,  q · k₃
```

每个分数是一个数字，越大表示越相关。假设得到 `[2, 0, -1]`。

### 第 2 步：softmax —— 把分数变成"加起来正好等于 1 的百分比"

**softmax 就是一个换算工具：输入任意一组数字（可正可负、可大可小），输出一组 0~1 之间、总和恰好为 1 的数字；而且它会放大差距——原来大的变得更大。**

它分三步做：

1. 每个数取自然常数 e（约 2.718）的次方，目的是把负数变成正数： 
   `e²≈7.39，e⁰=1，e⁻¹≈0.37`
2. 求和：`7.39 + 1 + 0.37 = 8.76`
3. 各自除以总和（这一步就叫**归一化**：把一组数按比例缩放到总和为 1）： 
   `7.39/8.76 ≈ 0.84，1/8.76 ≈ 0.11，0.37/8.76 ≈ 0.04`

于是 `[2, 0, -1]` → `[0.84, 0.11, 0.04]`。**这组数就是注意力权重**，含义是：理解当前位置时，第 1 个词参考 84%，第 2 个词参考 11%，第 3 个词参考 4%。

### 第 3 步：加权求和 —— 按百分比把内容混起来

**加权求和**就是：每个数先乘上自己的百分比，再全部加起来。

假设三个 token 的 `v`（内容）各是 2 维数字串：

```
v₁=[1, 0]，v₂=[0, 1]，v₃=[0.5, 0.5]
结果 = 0.84×[1,0] + 0.11×[0,1] + 0.04×[0.5,0.5]
     ≈ [0.87, 0.14]
```

这就是"结合上下文"的全部秘密：**当前这个词的最终表示 = 所有词的内容按相关度混在一起**。Q 负责问"我要找什么"，K 负责答"我这里有什么标签"，**真正被搬走的是 V**。

### 第 4 步：多头 —— 让 32 个专家各看一遍

上面是**一个头**的流程。真实模型里有几十个头（比如 32 个），**每个头有自己独立的一套 `W_Q/W_K/W_V`**，等于把同一句话投影到 32 个不同的视角里各分析一遍（有的头看句法，有的头看指代，有的头看位置）。最后把 32 份结果**拼接**回 `d_model` 维，再乘一张输出用的参数表 `W_O` 融合起来。

严谨说法：**每个 token 在每个头里，各有一组 q/k/v 向量。**

把公式合起来就是那行著名的式子：
$$
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}\left(
\frac{QK^{\mathrm T}}{\sqrt{d_{\mathrm{head}}}}
\right)V
$$


- `Kᵀ` 表示把 K 这张表**转置**（行变列、列变行），这样 Q 才能和它做点积；
- 形状变化：`(n×d_head) · (d_head×n) → (n×n)`，得到一个 n×n 的表格，第 i 行第 j 列的数就是"第 i 个词该关注第 j 个词多少"；
- 再乘 V：`(n×n) · (n×d_head) → (n×d_head)`。

##  d_head 是什么

**d_head（也写作 `d_k` 或 `head_dim`）= 单个注意力头内部的工作维度**，就是上面那个"一串数字有多长"的长度。

模型不拿 `d_model` 全部 4096 维一次性算注意力，而是**切成 n_heads 份，每份 d_head 维，各算各的，最后拼回来**：

```
d_model = n_heads × d_head
  4096  =    32    ×   128
```

| 符号      | 含义                                          | 典型值 |
| --------- | --------------------------------------------- | ------ |
| `d_model` | 描述一个 token 总共用多少个数字（主通道宽度） | 4096   |
| `n_heads` | 注意力头数（切成几份）                        | 32     |
| `d_head`  | **单个头内部用多少个数字**                    | 128    |

直觉比喻：**d_model 是主干道的宽度，d_head 是其中一条车道的宽度；n_heads 条车道并排，加起来的宽度正好等于主干道。**

第 1 节里 `W_Q` 的形状是 `4096 × 128`，意思就是：把 4096 个数字的表示，投影压缩到 128 个数字的子空间里去做匹配。

###  为什么要除以 $\sqrt{d_head}$

先看不除会怎样：**点积是 d_head 个数相乘再相加，参与相加的项越多，结果越容易变得很大。**

粗略地说：假设每个相乘结果随机在 +1 和 -1 之间，那 128 项加总后，结果的典型大小约在 **√128 ≈ 11** 这个量级（数字个数越多，累加结果的波动按"个数的平方根"增长）。维度再高，分数就能飙到几十上百。

而 softmax 有个脾气：**输入数字越大，它输出越极端**——一个接近 1，其余全接近 0。上面例子里输入 `[2,0,-1]` 得到 `[0.84,0.11,0.04]` 还算温和；如果输入变成 `[20,0,-10]`，输出会几乎是 `[1.00, 0.00, 0.00]`，等于**只盯着一个词、其余信息全丢**，而且这时再训练也很难调整（因为怎么微调，结果都是非 0 即 1）。

**所以除以 $\sqrt{d_head}$，就是把分数拉回"几个数字加减"的正常量级，防止 softmax 一家独大。**

⚠️ 注意是 **$\sqrt{d_head}$（√128），不是 $\sqrt{d_model}$（√4096）**——因为点积是在**头内部**做的，只有 128 维参与运算。

### 两个工程上常听到的词

**KV Cache（键值缓存）**

模型生成文本是**一个字一个字往外蹦**的。每蹦一个新字，理论上都要把前面所有 token 重算一遍 K 和 V——但前面这些 token 的 K/V 根本没变过。于是干脆**把它们存起来复用**，这就是 KV Cache。工程语境里随口说的"K/V 矩阵"，指的就是这个越攒越长的缓存表，**不是"每个 token 一份矩阵"**。

**GQA（Group Query Attention 分组查询注意力）**

Llama-3、Qwen 等模型用的省显存（显存 = 显卡的内存）技巧：让多个 Q 头**共用**一组 K/V 头，即 K/V 的头数比 Q 的头数少。注意**d_head 不变**，只是 K/V 缓存的份数变少了。

###  一句话记忆

> **参数是矩阵（共享）→ 每个 token 产出的是向量（只占一行）→ 摞起来才是 Q/K/V 矩阵；打分用点积，分数经 softmax 变成百分比，再按百分比把 V 加权求和；因为是在头内做的点积，所以缩放用 √d_head。**





## 1.4 KV Cache

既然每生成一个新 token，都要拿它的 Q 去和**前面所有 token** 的 K、V 计算，那前面的 K、V 从哪来？

两个选择：

1. **每次重算**：第 500 步要把前 499 个 token 全部重新过一遍模型 → 累计计算量 $O(n^2)$，绝对不可行
2. **缓存下来**：算过的 K、V 存进显存，每步只算新 token 的 Q/K/V，把新的 K、V **追加**进缓存

选 2。这份缓存就是 **KV Cache**。**代价**：随序列长度**线性增长**，是推理显存里唯一的动态大头。

## 1.5 Batch（批处理）

GPU 的强项是**一次算一堆**。把多个请求的 token 拼成一个大矩阵，一次矩阵乘法全算完，比一个一个算快几十倍。同一批一起跑的请求数叫 **batch size**。

- batch 越大 → GPU 越"吃饱" → **吞吐**越高
- batch 越大 → 显存越吃紧

## 1.6 激活与激活值

**激活（Activation）**：描述一个神经元被"点亮"的程度。

一个神经元做两件事：

$$
\begin{aligned}
z &= \sum_{i} w_i x_i + b && \text{（加权求和：输入的线性组合）}\\
a &= f(z) && \text{（过激活函数，得到输出）}
\end{aligned}
$$

**激活值（Activation）= 激活函数的输出 $a$ = 该神经元的最终输出**，它会被传给下一层，成为下一层的输入 $x$。

**为什么非要有激活函数 $f$**：没有它，整个网络会塌缩成一层线性变换。因为 $W_3 \cdot W_2 \cdot W_1 \cdot X$ 可以合并成**一个**矩阵 $W \cdot X$——100 层等价于 1 层。**激活函数引入"非线性"，把直线掰弯**，网络才能拟合复杂模式。

| 函数 | 公式 | 特点 |
|---|---|---|
| **ReLU** | $\max(0, z)$ | 当代基石，计算极快，缓解梯度消失 |
| **GELU** | 高斯平滑版 ReLU | BERT / GPT 系列使用 |
| **SwiGLU** | 门控变体 | **Llama / Qwen 等现代大模型标配** |

## 1.7 fp16 / 精度与字节

**fp16** = **f**loating **p**oint **16**，用 **16 bit = 2 字节**存一个小数。

| 名称 | 位数 | 字节 | 用途 |
|---|---|---|---|
| fp32 | 32 | 4 | 训练默认 |
| **fp16** | 16 | **2** | 推理常用，精度约 3~4 位有效数字，上限 65504 |
| **bf16** | 16 | **2** | 指数位 8 位（同 fp32），**范围大不易溢出**，训练首选 |
| fp8 / int8 | 8 | 1 | 量化推理，显存与带宽再减半 |

**为什么它重要**：精度每降一档，显存与**搬运字节数**都减半。对带宽瓶颈的 Decode 阶段，这几乎是成倍提速。

## 1.8 吞吐、SLO、P99

- **吞吐（Throughput）**：单位时间处理的 token 总数（tokens/s）。服务方最关心，因为它决定**每张卡能服务多少人 = 成本**
- **SLO**（Service Level Objective，服务等级目标）：给延迟定的承诺线，如"95% 请求 TTFT < 1s"。它是调优的**约束**：不是延迟与吞吐二选一，而是"**在满足 SLO 前提下把吞吐压榨到极限**"
- **P99（99 分位）**：100 个请求按延迟排序，第 99 个的值。**最慢的 1% 决定用户骂你的概率**
