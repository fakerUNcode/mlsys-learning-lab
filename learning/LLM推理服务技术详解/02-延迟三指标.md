# 二、延迟三指标

## 前置基础

**只用两个前置结论，其余不需要：**

1. **自回归串行定理**（§1.2）：输出 $N_{\text{out}}$ 个 token 必须走 $N_{\text{out}}$ 步，无法并行。因此"生成阶段总耗时 = 单步耗时 × 步数"
2. **分段可加性**：一个请求在时间轴上由若干**串行**阶段首尾相接组成，总耗时 = 各阶段耗时之和（这是加法的基本物理意义，不证）

> 注意：**不需要**任何关于显存、注意力机制的知识。本章只讲时间账。

## 公式推导

**第一步：定义 TTFT 的构成**

用户发请求 → 收到第一个 token，中间经过三段串行等待：

$$
\begin{aligned}
\text{TTFT} &= t_{\text{queue}} + t_{\text{prefill}} + t_{\text{net}} && \text{（分段可加：排队+计算+网络时延）}
\end{aligned}
$$

**第二步：定义生成阶段耗时**
$$
\begin{aligned}
T_{\text{gen}} &= \tau \cdot N_{\text{out}} && \text{（自回归串行：}N_{\text{out}}\text{ 步，每步 }\tau\text{）}
\end{aligned}
$$

其中 $\tau$ 就是 **TPOT** 的真实含义——**decode 单步耗时**。

**第三步：合成端到端延迟**
$$
\begin{aligned}
\text{E2E} &= \text{TTFT} + T_{\text{gen}} && \text{（分段可加：首字前 + 首字后）}\\
&= \text{TTFT} + \tau \cdot N_{\text{out}} && \text{（代入第二步）}\\
&= t_{\text{queue}} + t_{\text{prefill}} + t_{\text{net}} + \tau \cdot N_{\text{out}} && \text{（代入第一步，完全展开）}
\end{aligned}
$$

**第四步：长序列下 TTFT 可被忽略**
$$
\begin{aligned}
\lim_{N_{\text{out}} \to \infty} \frac{\text{TTFT}}{\text{E2E}} &= \frac{\text{TTFT}}{\text{TTFT} + \tau N_{\text{out}}} && \text{（代入第三步）}\\
&= \frac{\text{TTFT}}{\tau N_{\text{out}}} && \text{（}N_{\text{out}}\text{ 大时，}\tau N_{\text{out}} \gg \text{TTFT}\text{，分母略去 TTFT）}\\
&\to 0 && \text{（分母随 }N_{\text{out}}\text{ 线性发散）}
\end{aligned}
$$

**结论**：**短输出任务盯 TTFT，长输出任务盯 TPOT**。这是分开设 SLO 的数学依据。

**第五步：平均值会骗人——引入 ITL（**Inter-Token Latency，Token 间延迟**）**

定义第 $i$ 个 token 的**实际间隔** $\text{ITL}_i = t_i - t_{i-1}$，则：

$$
\begin{aligned}
\tau &= \frac{1}{N_{\text{out}}} \sum_{i=1}^{N_{\text{out}}} \text{ITL}_i && \text{（算术平均的定义）}
\end{aligned}
$$

平均值 $\tau$ 达标 **不能推出**每个 $\text{ITL}_i$ 都达标。反例：999 步各 1 ms、1 步被抢占 500 ms，则

$$
\begin{aligned}
\tau &= \frac{999 \times 1 + 1 \times 500}{1000} && \text{（代入平均定义）}\\
&= 1.499 \ \text{ms} && \text{（算术计算）}
\end{aligned}
$$

平均 1.5 ms 看着极好，但用户在这一次请求中**明确感受到了 500 ms 的卡顿**。所以必须监控 **P99 ITL**，不能只看平均 TPOT。

## 符号说明

| 符号 | 英文 / 读音 | 中文含义 | 单位 |
|---|---|---|---|
| $\text{E2E}$ | End-to-End | 端到端总延迟（请求发出→收完最后一个 token） | s |
| $\text{TTFT}$ | Time To First Token | 首 token 延迟 | s |
| $\tau$ | tau（希腊字母） | **TPOT 的本质**：decode 单步耗时 | s / token |
| $\text{TPOT}$ | Time Per Output Token | 平均每 token 输出耗时 | s / token |
| $\text{ITL}_i$ | Inter-Token Latency | 第 $i$ 个 token 与前一个的**实际**间隔 | s |
| $N_{\text{out}}$ | — | 输出 token 数（下标 out = output） | 个 |
| $t_{\text{queue}}$ | — | 排队等待时间（下标 queue = 队列） | s |
| $t_{\text{prefill}}$ | — | 预填充计算时间 | s |
| $t_{\text{net}}$ | — | 网络与调度开销 | s |
| $T_{\text{gen}}$ | — | 生成阶段总耗时（下标 gen = generation） | s |
| $P99$ | 99th percentile | 99 分位数（尾部延迟指标） | s |
| $\sum_{i=1}^{n}$ | sigma（希腊字母） | 求和算子，从 $i=1$ 累加到 $n$ | — |
| $\lim$ | limit | 取极限算子 | — |

## 程序实例

```python
def e2e(ttft_s: float, tpot_ms: float, n_out: int) -> float:
    """端到端延迟。tpot_ms 单位毫秒，其余秒。"""
    return ttft_s + (tpot_ms / 1000.0) * n_out

def slo_check(ttft_s, tpot_ms, n_out,
              ttft_slo=1.0, tpot_slo=0.05):
    """分别校验 TTFT 与 TPOT 是否达标。"""
    return {
        "TTFT": (ttft_s, ttft_slo, ttft_s <= ttft_slo),
        "TPOT_ms": (tpot_ms, tpot_slo * 1000, tpot_ms <= tpot_slo * 1000),
        "E2E_s": round(e2e(ttft_s, tpot_ms, n_out), 3),
    }

# 场景 A：TTFT 一般，但吐字快（长文本友好）
print("A:", slo_check(0.8, 20, 500))
# 场景 B：TTFT 极快，但吐字慢（交互友好、长文本灾难）
print("B:", slo_check(0.1, 80, 500))
```

**实际运行输出**：

```
A: {'TTFT': (0.8, 1.0, True), 'TPOT_ms': (20, 50.0, True), 'E2E_s': 10.8}
B: {'TTFT': (0.1, 1.0, True), 'TPOT_ms': (80, 50.0, False), 'E2E_s': 40.1}
```

**怎么读这个结果**：A 与 B 的 **TTFT 都达标**（0.8s 和 0.1s 都 < 1s），但 B 的 E2E 是 A 的 **3.7 倍**。如果只监控 TTFT，B 会被误判为"健康"——这就是必须同时设 TTFT 与 TPOT 双 SLO 的原因。

## 部署说明

| 业务形态 | 主要指标 | 典型 SLO | 调优方向 |
|---|---|---|---|
| **对话 / 实时助手** | TTFT | P95 < 1 s | 减排队、Prefix Cache、PD 分离 |
| **长文生成 / 翻译** | TPOT、P99 ITL | P99 < 50 ms | 大 batch、Chunked Prefill、权重量化 |
| **离线批处理** | 吞吐 | 不看延迟 | 尽量堆满 batch |
| **RAG / 长 Prompt** | TTFT | P95 < 2 s | Prefix Cache 命中率、FlashAttention |

**监控必须采集的四条曲线**：`TTFT(P50/P95/P99)`、`TPOT(均值)`、`ITL(P99)`、`E2E(P99)`。只看均值等于没监控。

## 直观理解

> 像下馆子：TTFT 是点完菜到上第一道菜，TPOT 是之后每道菜的间隔，E2E 是整顿饭吃完。第一道菜来得快不代表吃得快——后厨每道菜都得现炒，出菜间隔才决定你几点能走。
