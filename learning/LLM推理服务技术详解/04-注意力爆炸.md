# 四、注意力爆炸

## 前置基础

**只用两个前置结论：**

1. **矩阵乘法输出形状规则**：$(m \times k)$ 的矩阵乘以 $(k \times n)$ 的矩阵，结果是 $(m \times n)$，元素数为 $m \cdot n$
2. **张量显存 = 元素个数 × 每元素字节数**（§三 推导二已用）

> 补充名词：**HBM**（High Bandwidth Memory）是 GPU 主显存（A100 80GB），容量大但相对慢；**SRAM** 是 GPU 芯片上的超高速缓存，容量极小（几十 MB）但快得多。

## 公式推导

### 推导一：注意力分数矩阵的大小

推导 **Transformer 多头自注意力（MHA) 中，计算 $QK^\top$ 所产生的「注意力分数矩阵」占多少显存**

#### 第 0 步：先明确 Q、K 的形状

<img src="https://fakercodes.oss-cn-hangzhou.aliyuncs.com/sl/20260915133214url_20260915133206_h1_Oobw_20112bf9d40fb5b49fb622480ad59469.png" alt="img" style="zoom:25%;" />

多头注意力里，输入先做三次线性投影切成多头，使用张量写法：
$$
Q:[B,\;n_q,\;s,\;d_h]\qquad K:[B,\;n_{kv},\;s,\;d_h]\qquad V:[B,\;n_{kv},\;s,\;d_h]
$$
要确认 Q 中的某个元素；

1. 该 Query 位于哪个 Batch？即处理的是哪个请求，例如处理总数 Batch size =32 ,本次处理第 18 个请求。
2. 在该请求中，处理的是第几个头？
3. Q中的矩阵是由这样的向量堆叠而来的：s个(该请求的token数，等价于 n）维度为 $d_h$的向量组成，$d_h$含义为每个 token在单头中的向量位数

| 符号  | 含义                                                         |
| ----- | ------------------------------------------------------------ |
| $B$   | batch size，一次并行处理多少条样本                           |
| $n_q$ | Query 头数（MHA 下 $n_q=n_{kv}$；GQA/MQA 下 $n_q$ 是 $n_{kv}$ 的整数倍） |
| $s$   | 序列长度（sequence length），$$s \equiv n \equiv \text{单条序列的 token 数}$$ |
| $d_h$ | 单头维度，满足 $d_{model}=n_q\cdot d_h$                      |

#### 第 1 步：$QK^\top$ 的形状是怎么来的

注意力的核心计算是：

$$\text{score}=\frac{QK^\top}{\sqrt{d_h}}$$

把维度摆出来做矩阵乘法（只看最后两维，前面的 $B$、头数都是 batch 维）：

$$Q:(s,\;d_h)\;\times\;K^\top:(d_h,\;s)\;\longrightarrow\;(s,\;s)$$

- $K$ 原本是 $(s,\;d_h)$，转置后变成 $(d_h,\;s)$
- 中间那个维度 $d_h$ 被"缩掉"了（求和消掉）
- 剩下两个维度**都是 $s$**，于是得到 $s\times s=s^2$

GQA 场景下 $K$ 会先 broadcast/重复到 $n_q$ 份，所以最终：$$\boxed{\text{score 的形状}=[B,\;n_q,\;s,\;s]}$$

> **关键洞察**：$d_h$ 消失了，因为它是被求和收缩掉的维度。这也是为什么"改 head_dim 救不了显存"——决定显存的是 $s$，从头到尾和 $d_h$ 无关。

#### 第 2 步：数一数总共有多少个元素

把四个维度相乘：

$$N=B\cdot n_q\cdot s\cdot s=B\cdot n_q\cdot s^2$$

#### 第 3 步：每个元素占几个字节

这取决于计算精度：

| 精度            | 每元素字节数 $b$ |
| --------------- | ---------------- |
| fp32            | 4                |
| **fp16 / bf16** | **2** ← 本例     |
| fp8             | 1                |

#### 第 4 步：得到显存公式

$$M_{attn}=\underbrace{B\cdot n_q\cdot s^2}_{\text{元素个数}}\;\times\;\underbrace{b}_{\text{每元素字节}}\quad(\text{字节})$$

写成复杂度就是 $O(B\cdot n_q\cdot s^2)$，在 $B$、$n_q$ 固定时：**$O(s^2)$，平方级**。

#### 第 5 步：代入数值（图上那三个结果）

已知 $B=32,\;n_q=32,\;b=2$，先把常数项合并：

$$B\cdot n_q\cdot b=32\times32\times2=2048$$

所以公式简化成一个特别好记的形式：

$$M_{attn}=2048\cdot s^2\ \text{字节}$$

逐个代：

| $s$  | $s^2$           | 字节数                                          | 换算            |
| ---- | --------------- | ----------------------------------------------- | --------------- |
| 1000 | $1\times10^6$   | $2048\times10^6=2{,}048{,}000{,}000$            | **≈ 2.05 GB**   |
| 4000 | $1.6\times10^7$ | $2048\times1.6\times10^7=32{,}768{,}000{,}000$  | **≈ 32.77 GB**  |
| 8000 | $6.4\times10^7$ | $2048\times6.4\times10^7=131{,}072{,}000{,}000$ | **≈ 131.07 GB** |

⚠️ **一个容易对不上的坑**：图上用的是十进制 $1\ \text{GB}=10^9$ 字节（硬件厂商标称口径）。如果你用操作系统那种二进制 $1\ \text{GiB}=1024^3=1{,}073{,}741{,}824$ 字节，结果会小约 7%：

- $s=1000$：$2.048\times10^9 / 1.074\times10^9 \approx 1.91\ \text{GiB}$
- $s=8000$：$131.072\times10^9 / 1.074\times10^9 \approx 122.07\ \text{GiB}$

两种口径都对，别以为自己算错了。

#### 第 6 步：验证"平方增长"

|      | $s$  | $s$ 倍数 | $s^2$ 倍数 | 显存               |
| ---- | ---- | -------- | ---------- | ------------------ |
| ①    | 1000 | 基准     | 基准       | 2.05 GB            |
| ②    | 4000 | ×4       | ×16        | 32.77 GB（×16 ✓）  |
| ③    | 8000 | ×8       | **×64**    | 131.07 GB（×64 ✓） |

$2.05\times64=131.2\approx131.07$，完美吻合。**序列长度翻 8 倍，显存涨 64 倍**，这就是 $O(s^2)$ 的威力。

而 131 GB 已经远超单张 A100/H100 的 80 GB——**光这一个矩阵就装不下，更别提模型参数、优化器状态、激活值了**。

#### 补充：真实显存比上面算的还大得多

上面算的只是**一份** score 矩阵。朴素实现（如早期的 `nn.MultiheadAttention`）实际峰值还要乘上好几倍：

1. **前向要同时活着两份** $O(s^2)$：softmax 前的 `score` + softmax 后的注意力权重 $A$
2. **反向还要用它们算梯度**，这两份不能提前释放
3. **dropout mask**：再来一份 $O(s^2)$
4. **attention mask / causal mask**：又一份 $O(s^2)$

所以真实峰值往往是理论值的 **2–4 倍**——$s=8000$ 时朴素实现可能需要 300+ GB。



### 推导三：FlashAttention 如何把 $O(s^2)$ 降到 $O(s)$

**核心思想**：**不把这个 $s \times s$ 矩阵真正写进 HBM**，而是切成块在 SRAM 里算完、当场汇总。

#### 先建立一个贯穿全文的画面：桌面 vs 仓库

GPU 里有两级存储，速度和容量完全不成比例：

|                      | 类比             | 真实容量                | 速度                     |
| -------------------- | ---------------- | ----------------------- | ------------------------ |
| **SRAM**（片上缓存） | 你**手边的桌面** | 很小（A100 上约 20 MB） | 极快（带宽 ~19 TB/s）    |
| **HBM**（显存）      | **楼下的仓库**   | 很大（40 / 80 GB）      | 慢得多（带宽 ~1.5 TB/s） |

**关键事实**：GPU 真正的算力其实强到离谱，但大多数时候它**在等数据从仓库搬上桌面**。Transformer 里 softmax、dropout 这些操作慢，主要不是算得慢，而是**搬运慢**。

所以优化的真正目标有两个：

1. **别在仓库里摊一张 s×s 的大草稿纸**（省显存）
2. **少跑几趟楼梯去仓库**（省时间）

FlashAttention 一次性把两件事都办了。

#### 一、先问一个根本问题：那个 s×s 矩阵真的必要吗？

回顾一下注意力的完整流程（$d_h$ 是 head dim）：

$$S=QK^\top\quad\rightarrow\quad P=\text{softmax}(S)\quad\rightarrow\quad O=PV$$

| **矩阵**              | **形状**      | **是不是"必需品"？**     |
| :-------------------- | :------------ | :----------------------- |
| $S=QK^\top$           | $s\times s$   | ❌ 中间产物               |
| $P=\text{softmax}(S)$ | $s\times s$   | ❌ 中间产物               |
| **$O=PV$**            | $s\times d_h$ | ✅ **这才是我们要的答案** |

**顿悟点就在这里**：$s×s$ 那张纸，从头到尾只是**中间草稿**。我们真正想要的，只是最后那张小小的 $s×d_h$。

> **类比**：老师要算全班 50 人的平均分。他可以先把 50 个分数工工整整抄到一张大纸上，再一个个加起来——但那张大纸只是草稿，用完就扔。更聪明的做法是：心里只记"当前总分 + 当前人数"，报一个加一个，大纸根本不用摊开。

FlashAttention 干的就是这件事：**草稿纸只在桌面上小范围摊开，用完即弃，绝不搬到仓库去**。

#### 二、怎么分块？Q 横着切，K/V 竖着切

##### 切法

设桌面一次能放下 $B_r 行、B_c 列$的一小块。

- **Q 按行切**：切成 $⌈s/B_r⌉$ 块，每块 $Q_i$ 形状 $(B_r,d_h)$
- **K、V 按列切**（其实是按 token 切）：切成 $⌈s/B_c⌉$ 块，每块 $K_j、V_j$ 形状 $(B_c,d_h)$

为什么这样切？因为这样切出来的**运算结果，恰好就是输出 O 的一整行块**：

<img src="https://fakercodes.oss-cn-hangzhou.aliyuncs.com/sl/20260915131828url_20260915131744_h1_MPnO_4d578d2b62f7a58adbb7a8e12aa56d31.png" alt="img" style="zoom: 25%;" />
$$
\underbrace{Q_i}_{(B_r,d_h)}\times\underbrace{K_j^\top}_{(d_h,B_c)}\longrightarrow\underbrace{S_{ij}}_{(B_r,B_c)}\quad\xrightarrow{\text{softmax}}\quad\underbrace{P_{ij}}_{(B_r,B_c)}\times\underbrace{V_j}_{(B_c,d_h)}\longrightarrow\underbrace{O_i}_{(B_r,d_h)}
$$
重点看最后那个 $O_i$：它是**输出 O 的第 i 个行块**，形状$(B_r,d_h)$，**和 s 无关**。

> **为什么必须是"Q 按行、K/V 按列"？**
>
> 因为输出的第 i 行，需要的是 Q 的第 i 行 与 **所有** K 的匹配。所以外层循环固定一个 Q 行块，内层循环把所有 K、V 块扫一遍——扫完之后，O 的这一行块就**彻底算完了，可以写回仓库，再也不用管**。
>
> 这是整个算法能省显存的关键：**每一块$O_i$只被写回一次，不会回头改**。

#### 伪代码（先看骨架，softmax 的细节下一节补）

```py
for i in range(s // B_r):              # 外层：逐个 Q 行块
    Q_i = load(Q[i*B_r:(i+1)*B_r])     # 搬 Q 块上桌面（一次，之后一直复用）
    O_i, m_i, l_i = 0, -inf, 0         # 输出块 + 两个"记账本"
    for j in range(s // B_c):          # 内层：扫过所有 K/V 块
        K_j, V_j = load(...)           # 搬 K/V 块上桌面
        S_ij = Q_i @ K_j.T             # (B_r, B_c) 小矩阵，只在桌面
        ...  # 在线 softmax + 累加，见下一节
        O_i = update(O_i, S_ij, V_j)
        free(K_j, V_j, S_ij)           # ← 关键：立刻扔掉，绝不写回仓库
    save(O_i)                          # 这一行块彻底完成，写回一次
```

注意第 8 行的 `free`：**Sij 从来没去过仓库**。它生在桌面、死在桌面，仓库对它一无所知。

#### 三、显存为什么变成 O(s)：清点一下仓库里到底放了什么

现在我们来"查账"。整个计算过程中，仓库（HBM）里必须长期存在的东西：



| 东西          | 形状            | 复杂度             |
| ------------- | --------------- | ------------------ |
| 输入 $Q$      | $s\times d_h$   | $O(s)$             |
| 输入 $K$      | $s\times d_h$   | $O(s)$             |
| 输入 $V$      | $s\times d_h$   | $O(s)$             |
| 输出 $O$      | $s\times d_h$   | $O(s)$             |
| ~~$S$ / $P$~~ | ~~$s\times s$~~ | **❌ 根本不存在了** |

$$ M_{HBM}=O(s)+O(s)+O(s)+O(s)=\boxed{O(s)}$$

这就是图上那个 $MHBM=O(s)$ 的来历——**不是因为压缩了什么，而是那个 $s^2$ 的大矩阵压根没被生出来**。

而桌面（SRAM）上同时存在的只有：一块 $Q_i$、一块 $K_j$、一块 $V_j$、一块 $S_{ij}$：

$$M_{SRAM}=O(\underbrace{B_r d_h}_{Q_i}+\underbrace{B_c d_h}_{K_j}+\underbrace{B_c d_h}_{V_j}+\underbrace{B_r B_c}_{S_{ij}})$$

因为 $B_r$、$B_c$ 是**固定常数**（由桌面大小决定，比如 64、128），和 $s$ 无关，所以：

$$M_{SRAM}=O(B_r B_c)=O(1)\quad\text{（对 }s\text{ 而言是常数）}$$

这就是图上 $M_{block}$、$M_{SRAM}=O(B_rB_c)$ 的含义。

#### 用回第一份推导的数字感受一下

$B=32,\ n_q=32,\ s=8000,\ b=2$：



|            | 朴素实现                                          | FlashAttention | 倍数 |
| ---------- | ------------------------------------------------- | -------------- | ---- |
| score 显存 | $32\times32\times8000^2\times2\approx$ **131 GB** | **约 0**       | ∞    |
| Q+K+V+O    | 约 0.5 GB                                         | 约 0.5 GB      | 1×   |

那 131 GB 不是被"压缩"了，是**从未被申请过**。这就是"免费"的含义。

#### 四、最难的一关：在线 softmax（为什么分块还能算对？）

这是整份推导里唯一真正烧脑的地方。前面都好说，但有人会问：

> softmax 不是要**看完一整行**才能算吗？它要求出**全局最大值**和**全局求和**。你一块一块地看，怎么可能算出一样的结果？

##### 4.1 先看 softmax 到底在算什么

对 $Q$ 的第 $i$ 行（一个 query），输出是 $V$ 的加权平均：

$$o_i=\frac{\sum_{j=1}^{s}e^{q_i\cdot k_j-m}\cdot v_j}{\sum_{j=1}^ {s}e^{q_i\cdot k_j-m}}\qquad m=\max_j(q_i\cdot k_j)$$

老老实实算，需要：

- $m$：**全局**最大值（要扫完所有 $j$）
- $\ell$：**全局**求和（要扫完所有 $j$）

两个都要求"看完一整行"，这就是为什么朴素实现必须先把整行 $S[i,:]$ 摊在纸上。**这是分块的最大障碍。**

##### 4.2 为什么要减最大值？—— 一句题外话但很重要

注意公式里那个 $e^{x-m}$。减 $m$ 是为了**数值稳定**：$e^{13}$ 已经是几十万，$e^{100}$ 直接溢出成 `inf`。减掉最大值后，指数最大是 $e^0=1$，永远不会爆。

**而 FlashAttention 的所有麻烦，都来自这个"减最大值"**——因为分块时你不知道全局最大值是多少。

##### 4.3 解法：记账本 + 汇率换算

FlashAttention 的思路是**增量更新**。它维护三个东西，我称之为"一本账"：



| 变量     | 含义                   | 类比                   |
| -------- | ---------------------- | ---------------------- |
| $m_i$    | 目前见过的**最大值**   | "到目前为止的最高分"   |
| $\ell_i$ | 目前见过的**加权分母** | "到目前为止的权重总和" |
| $o_i$    | 目前的**部分输出**     | "到目前为止的加权平均" |



**核心洞察**：之前算好的部分**可以事后补救**，只要乘一个修正因子。所以永远不需要回头重算，也不需要保存历史数据。

##### 4.4 递推公式

![online-softmax-corrected](https://fakercodes.oss-cn-hangzhou.aliyuncs.com/sl/online-softmax-corrected.png)

处理第 $j$ 个 K/V 块时：

**① 先算这一块的局部情况**

$$m_{ij}=\max_j(S_{ij})\qquad\text{（本块内的最大值）}$$

$$\tilde P_{ij}=\exp(S_{ij}-m_{ij})\qquad\text{（本块的未归一化权重，最大值为 }e^0=1\text{）}$$

$$\ell_{ij}=\text{rowsum}(\tilde P_{ij})\qquad\text{（本块权重之和）}$$

**② 更新全局最大值**（账本里的"最高分"可能被刷新）

$$m_i^{new}=\max\big(m_i^{old},\;m_{ij}\big)$$

**③ 关键一步：用"汇率"把旧账换算过来**

$$\alpha=e^{\,m_i^{old}-m_i^{new}}\qquad\text{（旧最大值相对新最大值的比值，}\in(0,1]\text{）}$$

$$\ell_i^{new}=\underbrace{\alpha\cdot\ell_i^{old}}_{\text{旧账按新汇率折算}}\;+\;\underbrace{e^{\,m_{ij}-m_i^{new}}\cdot\ell_{ij}}_{\text{新块按新汇率折算}}$$

$$o_i^{new}=\underbrace{\alpha\cdot o_i^{old}}_{\text{旧输出折算}}\;+\;\underbrace{e^{\,m_{ij}-m_i^{new}}\cdot\tilde P_{ij}V_j}_{\text{新块的贡献}}$$

**④ 内层循环结束后，做最后一次归一化**

$$O_i=\frac{o_i}{\ell_i}$$

##### 4.5 为什么这样"等价"？三行就能看懂

把指数拆开看（设最终全局最大值为 $m^{final}$，第 $j$ 块的局部最大值是 $m_j$）：

$$e^{s_{ij}-m^{final}}=\underbrace{e^{s_{ij}-m_j}}_{\text{块内先算的}}\times\underbrace{e^{m_j-m^{final}}}_{\text{事后补的汇率}}$$

**乘法可以拆解成"先算一块 × 事后补一个系数"**——这就是在线 softmax 能成立的**全部数学基础**，本质上只是 $e^{a+b}=e^a\cdot e^b$。

每一块的权重在最终分母里的比例，和一次性算出来的**完全一模一样**：

> **结论：结果不是"近似"，是逐位相同的精确等价（up to floating point）。** 这是 FlashAttention 能无缝替换标准 attention 的原因——你换个实现，模型输出一个字都不会变。4.6 一个数值稳定的小细节

注意 $\alpha=e^{m^{old}-m^{new}}$：因为 $m^{new}\ge m^{old}$，指数恒 $\le 0$，所以 $\alpha\in(0,1]$，**只会把旧账缩小，永远不会放大**——不会出现数值爆炸。同理 $e^{m_{ij}-m^{new}}\le1$。

这也是为什么必须维护 $m$ 而不是随便减一个常数：**保证所有修正因子都不大于 1，误差不会累积放大。**

#### 五、顺带解决的第二件事：HBM 读写次数

前面一直在讲**省显存**。但 FlashAttention 其实**更快**，原因就在这儿。

回顾仓库/桌面的类比：真正的瓶颈是**跑楼梯的次数**，不是算的速度。

**朴素实现**要把 $S$、$P$ 这些 $s\times s$ 的大矩阵在仓库和桌面之间来回搬：

$$\text{HBM 读写}=O(\underbrace{sd}_{\text{读写 }Q,K,V}+\underbrace{s^2}_{\text{读写 }S,P})$$

那个 $s^2$ 是主要开销。

**FlashAttention**：$Q_i$ 每个外层循环只读 1 次；$K_j$、$V_j$ 在内层循环扫一遍；$O_i$ 只写 1 次。全程没有 $s^2$ 的搬运：

$$\text{HBM 读写}=O(sd+s)=O(sd)$$

> ⚠️ **严谨性补充**：图上写的 $O(s)$ 是简化的说法。按 FlashAttention 原论文，实际是 $O\!\left(\dfrac{s^2d^2}{M}\right)$（$M$ 是 SRAM 大小）。
>
> 但因为 $d$ 通常只有 64/128，而 $M$ 有几十 MB，$d^2/M$ 是个很小的系数（$\ll 1$），**实际表现接近线性**，远优于朴素实现的 $s^2$ 项。所以"从 $O(s^2)$ 降到 $O(s)$"作为直觉理解是对的，写论文时记得用括号里那个式子。

|                    | 朴素 Attention    | FlashAttention               | 怎么做到的                                 |
| ------------------ | ----------------- | ---------------------------- | ------------------------------------------ |
| **score 矩阵显存** | $O(s^2)$ ← 131 GB | **$O(s)$**（≈0，根本没生成） | 分块算，只在 SRAM 里活一瞬间               |
| **SRAM 占用**      | —                 | $O(B_rB_c)$，与 $s$ 无关     | 块大小是常数                               |
| **HBM 读写**       | $O(s^2+sd)$       | $O(s^2d^2/M)\approx O(sd)$   | fused kernel，搬运次数大减                 |
| **结果精度**       | 基准              | **完全一致（非近似）**       | 在线 softmax + 汇率修正                    |
| **代价**           | —                 | 反向要**重算**一次           | 用算力换显存（FLOPs 多了，但墙上时间更短） |

#### 三句话记住它

1. **为什么省显存**：$s\times s$ 只是草稿纸，FlashAttention 让它在桌上小范围摊开、用完即扔，从不搬进仓库——**不是压缩，是从未生成**。
2. **为什么能算对**：softmax 的分母可以"事后补救"（$e^{a+b}=e^ae^b$），每来一块就用汇率 $e^{m_{old}-m_{new}}$ 把旧账折算一下，**结果逐位相同**。
3. **为什么还更快**：真正的瓶颈是仓库↔桌面的搬运次数，把 $s^2$ 的搬运干掉后，虽然多算了一遍（反向重算），**墙上时间反而更短**。

> 可以这样自测：如果有人问"FlashAttention 是不是用精度换显存的近似算法"，能立刻答出"**不是，它是精确算法，只是把矩阵分块并用在线 softmax 保证等价**"，这一节就算真懂了。符号说明

## 程序实例

```python
def attn_matrix_bytes(batch, n_q_heads, seq_len, dtype_bytes=2):
    return batch * n_q_heads * seq_len * seq_len * dtype_bytes

print("注意力分数矩阵显存（B=32, heads=32, fp16）")
for s in (1000, 2000, 4000, 8000):
    gb = attn_matrix_bytes(32, 32, s) / 1e9
    flag = "  <-- 超过 80GB 单卡容量" if gb > 80 else ""
    print(f"  s={s:5d} -> {gb:8.2f} GB{flag}")

print("\n平方验证: M(8000)/M(1000) = %.1f  (8^2 = 64)"
      % (attn_matrix_bytes(32,32,8000) / attn_matrix_bytes(32,32,1000)))
```

**实际运行输出**：

```
注意力分数矩阵显存（B=32, heads=32, fp16）
  s= 1000 ->     2.05 GB
  s= 2000 ->     8.19 GB
  s= 4000 ->    32.77 GB
  s= 8000 ->   131.07 GB  <-- 超过 80GB 单卡容量

平方验证: M(8000)/M(1000) = 64.0  (8^2 = 64)
```

## 部署说明

- **现代推理框架默认已启用 FlashAttention 或其后继（FlashInfer）**，一般无需手动开关；若自己写模型代码，务必用 `torch.nn.functional.scaled_dot_product_attention` 或 `flash_attn` 库，**不要手写 `Q @ K.T`**
- **长上下文场景还需配合**：`--max-model-len` 合理设限、KV 量化、以及必要时用 **KV Cache 卸载到 CPU**（长但不活跃的请求）
- **判别方法**：如果显存占用随上下文长度呈"加速上升"而非线性上升，说明注意力矩阵被实体化（materialize）了，应检查是否真的走了 Flash 内核

## 直观理解

> 一群人开会两两互评，n 个人要填 n×n 张表：100 人 1 万张还行，800 人 64 万张桌子就放不下了。FlashAttention 的办法是不把表全摊开，一次只填一小格、当场折算进总分并只保留两个累计数字，桌上永远只有一小叠纸。
