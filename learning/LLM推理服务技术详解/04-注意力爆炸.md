# 四、注意力爆炸

## 前置基础

**只用两个前置结论：**

1. **矩阵乘法输出形状规则**：$(m \times k)$ 的矩阵乘以 $(k \times n)$ 的矩阵，结果是 $(m \times n)$，元素数为 $m \cdot n$
2. **张量显存 = 元素个数 × 每元素字节数**（§三 推导二已用）

> 补充名词：**HBM**（High Bandwidth Memory）是 GPU 主显存（A100 80GB），容量大但相对慢；**SRAM** 是 GPU 芯片上的超高速缓存，容量极小（几十 MB）但快得多。

## 公式推导

### 推导一：注意力分数矩阵的大小

注意力要求"每个 token 对其他所有 token 的关注度"，即计算 $Q K^{\top}$：

$$
\begin{aligned}
\text{shape}(Q K^{\top}) &= [\,B,\ n_q,\ s,\ s\,] && \text{（矩阵乘法形状规则：}Q[s \times d]\cdot K^{\top}[d \times s]{=}[s \times s]\text{，再乘 batch 与头数）}\\
M_{\text{attn}} &= B \cdot n_q \cdot s \cdot s \cdot b && \text{（元素数 = 各维连乘，再乘每元素字节）}\\
&= B \cdot n_q \cdot s^{2} \cdot b && \text{（合并 }s \cdot s = s^{2}\text{）}
\end{aligned}
$$

**关键观察**：$s$ 出现了**两次**，所以这是 **$O(s^2)$ 平方级增长**，而不是线性。

代入（$B = 32$ 条并发，$n_q = 32$ 头，fp16 即 $b = 2$）：

$$
\begin{aligned}
M_{\text{attn}}(s{=}1000) &= 32 \times 32 \times 1000^{2} \times 2 && \text{（代入）}\\
&= 2.05\ \text{GB} && \text{（计算后除以 }10^{9}\text{）}\\
M_{\text{attn}}(s{=}4000) &= 32 \times 32 \times 4000^{2} \times 2 && \text{（代入）}\\
&= 32.77\ \text{GB} && \text{（计算后除以 }10^{9}\text{）}\\
M_{\text{attn}}(s{=}8000) &= 32 \times 32 \times 8000^{2} \times 2 && \text{（代入）}\\
&= 131.07\ \text{GB} && \text{（计算后除以 }10^{9}\text{）}
\end{aligned}
$$

**序列长度从 1000 涨到 8000（8 倍），显存涨到 64 倍（$8^2$），直接超过单卡 80GB 容量。**

### 推导二：验证平方关系

$$
\begin{aligned}
\frac{M_{\text{attn}}(8000)}{M_{\text{attn}}(1000)} &= \frac{B\, n_q\, (8000)^{2}\, b}{B\, n_q\, (1000)^{2}\, b} && \text{（代入公式，写成比值）}\\
&= \left(\frac{8000}{1000}\right)^{2} && \text{（约去公因子 }B\, n_q\, b\text{）}\\
&= 8^{2} && \text{（计算比值）}\\
&= 64 && \text{（计算平方）}
\end{aligned}
$$

与 $\dfrac{131.07}{2.05} = 63.9$ 吻合（差值是取整误差）。

### 推导三：FlashAttention 如何把 $O(s^2)$ 降到 $O(s)$

**核心思想**：**不把这个 $s \times s$ 矩阵真正写进 HBM**，而是切成块在 SRAM 里算完、当场汇总。

把 $Q$ 按行切成大小为 $B_r$ 的块，把 $K, V$ 按列切成大小为 $B_c$ 的块：

$$
\begin{aligned}
M_{\text{block}} &= B_r \cdot B_c \cdot b && \text{（单个小块的字节数，与 }s\text{ 无关）}\\
M_{\text{SRAM}} &= O(B_r B_c) && \text{（SRAM 中驻留的块，是常数级）}\\
M_{\text{HBM}} &= O(s) && \text{（HBM 中只存 }Q, O\text{ 与 softmax 统计量，不存 }s{\times}s\text{ 矩阵）}
\end{aligned}
$$

**为什么"分块 + 在线 softmax"能等价于一次性算**：softmax 需要全局最大值 $m$ 与全局和 $\ell$ 做归一化。分块时逐块更新这两个**标量统计量**，最终结果与一次性计算**数值等价**（不是近似）：

$$
\begin{aligned}
m^{\text{new}} &= \max(m^{\text{old}},\ \tilde{m}) && \text{（在线最大值更新：取历史最大与当前块最大）}\\
\ell^{\text{new}} &= e^{m^{\text{old}} - m^{\text{new}}} \ell^{\text{old}} + e^{\tilde{m} - m^{\text{new}}} \tilde{\ell} && \text{（用统一基准 }m^{\text{new}}\text{ 重新缩放后相加）}
\end{aligned}
$$

**收益**：显存 $O(s^2) \to O(s)$，**HBM 读写次数也同量级下降**。因为瓶颈在搬运而不在计算（§五会证明），IO 的下降直接转化为加速。

## 程序实例

```python
def attn_matrix_bytes(batch, n_q_heads, seq_len, dtype_bytes=2):
    return batch * n_q_heads * seq_len * seq_len * dtype_bytes

print("注意力分数矩阵显存（B=32, heads=32, fp16）")
for s in (1000, 2000, 4000, 8000):
    gb = attn_matrix_bytes(32, 32, s) / 1e9
    flag = "  <-- 超过 80GB 单卡容量" if gb > 80 else ""
    print(f"  s={s:5d} -> {gb:8.2f} GB{flag}")

print("\n平方验证: M(8000)/M(1000) = %.1f  (8^2 = 64)"
      % (attn_matrix_bytes(32,32,8000) / attn_matrix_bytes(32,32,1000)))
```

**实际运行输出**：

```
注意力分数矩阵显存（B=32, heads=32, fp16）
  s= 1000 ->     2.05 GB
  s= 2000 ->     8.19 GB
  s= 4000 ->    32.77 GB
  s= 8000 ->   131.07 GB  <-- 超过 80GB 单卡容量

平方验证: M(8000)/M(1000) = 64.0  (8^2 = 64)
```

## 部署说明

- **现代推理框架默认已启用 FlashAttention 或其后继（FlashInfer）**，一般无需手动开关；若自己写模型代码，务必用 `torch.nn.functional.scaled_dot_product_attention` 或 `flash_attn` 库，**不要手写 `Q @ K.T`**
- **长上下文场景还需配合**：`--max-model-len` 合理设限、KV 量化、以及必要时用 **KV Cache 卸载到 CPU**（长但不活跃的请求）
- **判别方法**：如果显存占用随上下文长度呈"加速上升"而非线性上升，说明注意力矩阵被实体化（materialize）了，应检查是否真的走了 Flash 内核

## 直观理解

> 一群人开会两两互评，n 个人要填 n×n 张表：100 人 1 万张还行，800 人 64 万张桌子就放不下了。FlashAttention 的办法是不把表全摊开，一次只填一小格、当场折算进总分并只保留两个累计数字，桌上永远只有一小叠纸。
