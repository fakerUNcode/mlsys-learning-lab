## 第 1 题（基础：显存账）

> 一台机器装有 **A100 80GB × 1**，部署 **Llama-3 8B**（GQA 配置）。已知：
> - 层数 $L = 32$，**KV 头数 $n_{kv} = 8$**，头维度 $d_{\text{head}} = 128$
> - 权重使用 **fp16**（2 byte），KV Cache 也使用 fp16
> - 激活值与框架预留合计 **6 GB**
> - 业务平均序列长度（prompt + 输出）$\bar{s} = 2000$ token
>
> 请计算：
> 1. 权重占用多少 GB？
> 2. 单个 token 的 KV Cache 是多少 KiB？（写出公式与代入过程）
> 3. 可用于 KV Cache 的显存是多少 GB？
> 4. 理论上最多能同时服务多少条请求？

## 第 2 题（进阶：延迟账 + 策略选择）

> 承接第 1 题的部署，现在已知：
> - A100 的 fp16 算力峰值 $\mathcal{F} = 312$ TFLOP/s，带宽 $\mathcal{B} = 2.0$ TB/s
> - 某批请求正在以 $B = 64$ 的 batch 做 decode，平均上下文 $s = 2000$
> - 此时调度器决定在这一步插入一个 **$s_p = 6000$ token 的长 prefill**
>
> 请计算：
> 1. **插入前**这一步的耗时 $\tau$（需分别算出 $t_{\text{calc}}$ 与 $t_{\text{mem}}$，并说明取哪个）
> 2. **插入后**这一步的耗时 $\tau'$
> 3. 尖刺倍数 $\tau' / \tau$
> 4. 若启用 Chunked Prefill 且块大小 $c = 512$，新的单步耗时 $\tau''$ 是多少？尖刺被压到多少倍？
> 5. **开放题**：结合 §五 的 $I^{*}$ 判据，说明为什么"把 chunk 切得更小"不能无限制地改善延迟——切到极致会发生什么？
