# Tensor 学习术语表

本页统一 T02/T03 中反复出现的词。“位置”是容易混淆的口语词：讨论 Tensor 下标时写“逻辑坐标/索引”；讨论一块 storage 内元素编号时写“storage 槽位”；讨论 CPU/GPU 可访问指针时写“运行时地址”。三者不是一回事。

| 术语 | 本课程中的意思 | 小例子 |
|---|---|---|
| Tensor | 带 shape、dtype、device 等元数据的多维数组 | `[[10,20,30],[40,50,60]]` |
| shape | 各轴的长度，规定合法坐标范围 | shape `(2,3)` 表示第 0 轴合法索引为 0、1，第 1 轴合法索引为 0、1、2 |
| 轴（axis）/维度 | Tensor 中一个独立变化的方向；编号从 0 开始 | `(2,3)` 有轴 0 和轴 1；`ndim` 是轴的数量 2 |
| 索引/逻辑坐标 | 用一组从 0 开始的轴编号唯一指明逻辑元素 | `x[1,2]` 是轴 0 取索引 1、轴 1 取索引 2 |
| 逻辑顺序 | 按 Tensor 的 shape 和轴顺序读取元素的顺序；二维默认按行读取 | `[[0,1,2],[3,4,5]]` 按行读为 `0,1,2,3,4,5` |
| storage | Tensor 所引用的一段底层元素存储 | 一段可按槽位编号的线性元素区域 |
| storage 槽位/元素偏移 | 在某一块 storage 内从 0 开始数的元素偏移，不是逻辑坐标也不是运行时地址 | 槽位 4 表示这一块 storage 的第 5 个元素 |
| storage offset | Tensor 的逻辑坐标 `(0,...,0)` 从其 storage 的哪个槽位开始 | 切片可能从槽位 3 开始，所以 offset 为 3 |
| stride | 逻辑坐标沿某轴加 1 时，storage 槽位增加多少；单位是元素，不是字节 | shape `(2,3)`、stride `(3,1)` 时，行进一格加 3，列进一格加 1 |
| 运行时地址 | CPU 虚拟地址或 GPU 设备指针，供运行时访问存储；不是我们能直接查看的 RAM 硬件物理地址 | `data_ptr()` 返回的地址值 |
| contiguous/连续 | 按指定内存格式遍历逻辑元素时，元素是否按该格式紧密排列 | 默认行优先的 `(2,3)` 通常 stride `(3,1)`，是连续布局 |
| view/视图 | 新 Tensor 元数据引用原 storage；共享存储 | `x.view(...)` 成功时，写入对应槽位会影响 `x` |
| copy/复制 | 把值写到另一块 storage | dtype 转换、跨设备传输或不连续 Tensor 的 `contiguous()` 通常会复制 |

## 一个坐标如何对应到槽位

令 `x = [[10, 20, 30], [40, 50, 60]]`，shape 为 `(2,3)`，默认连续 stride 为 `(3,1)`。`x[1,2]` 中的 `(1,2)` 是逻辑坐标：沿第 0 轴取索引 1、沿第 1 轴取索引 2。若 storage offset 是 0，它映射到槽位 `0 + 1×3 + 2×1 = 5`，该槽位保存数值 `60`。逻辑坐标 `(1,2)`、storage 槽位 `5`、运行时地址是三个不同概念。

## 最重要的区别

```text
shape：坐标能取哪些值、每轴多长
stride：坐标变化时，storage 槽位怎样变化
storage offset：逻辑坐标起点从 storage 哪个槽位开始
运行时地址：这一块 storage 实际交给 CPU/GPU 访问的指针
```

shape 不能单独确定实际 stride。相同 shape 的 Tensor 可以使用不同 stride，例如连续矩阵和它的转置视图。只有额外指定“默认连续布局”时，才能由 shape 推算该布局所需的标准 stride。

图中的槽位编号只表示**各自 storage 内的元素偏移**。两个不同 storage 都有槽位 0；它们不是同一个存储单元。CPU 和 GPU 的槽位编号也各属于自己的设备存储。
