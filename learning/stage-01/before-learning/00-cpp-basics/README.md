# 语法地基

本节是阶段 1 的第 `00` 节。它不要求你提前掌握 C++，目标是先建立一套稳定的读码方法，再进入生命周期、智能指针和 STL 等主题。

## 学习目标

完成本节后，你应该能够：

- 区分声明、定义、表达式、语句和作用域；
- 从复杂类型中找到“核心类型”以及 `const`、`&`、`*` 的作用；
- 看懂函数的参数传递、返回值和调用过程；
- 阅读 `vector<int>`、`optional<int>` 和 `variant<A, B>` 等模板类型；
- 解释 `auto`、结构化绑定、引用、指针和移动分别解决什么问题；
- 沿着现有示例的数据流阅读代码，而不是逐个符号猜测。

## 前置基础

本节只假定三个旧概念：

1. **变量**：程序运行时保存数据的名字。
2. **函数**：接收输入、完成任务并返回结果的一段代码。
3. **内存**：程序保存对象和指令的空间。

若这些概念已经模糊，可以先带着直觉阅读；正文会在使用处重新说明。

## 核心关系

阅读 C++ 程序时，先追踪数据，再追踪类型和生命周期：

```text
输入文本
⇒（函数调用）解析结果
⇒（分支判断）数组或错误
⇒（只读借用）计算总和
⇒（作用域结束）自动清理
```

这条链也是当前 Stage 1 示例的运行主线。后面的每个语法点都会回到这条链上。

## 符号说明

- `T`：泛型代码中尚未指定的类型。
- `&`：在本节类型声明中表示引用。
- `*`：在本节类型声明中表示指针。
- `&&`：右值引用，移动语义章节会继续展开。
- `std`：C++ 标准库使用的命名空间。
- RAII：资源获取即初始化，用对象生命周期管理资源。

## 通过标准

不要用“已经看过”作为通过标准。你需要不查答案完成以下任务：

- 给别人讲清 `runtime_demo.hpp` 与 `runtime_demo.cpp` 的分工；
- 解释 `const std::vector<int>&` 为什么没有复制数组；
- 解释 `ParseResult` 为什么只能处于成功或失败中的一种状态；
- 指出 `string_view` 查看的是谁的字符，以及字符至少要活多久；
- 阅读 `main.cpp`，按顺序说出每个对象由谁拥有、何时销毁。

## 主线联系

CUDA Host 代码也由这些基础结构组成：头文件声明接口，`.cpp` 或 `.cu` 文件提供实现，引用传递 Tensor 元数据，指针表示内存地址，RAII 对象管理 Stream、Event 或显存。`00` 节学的是以后读 CUDA Runtime API 时必须使用的语言工具。

ctest --test-dir build/stage1-lifetime --output-on-failure

这一步不是部署线上服务，而是把教学源码配置、编译并测试成可运行程序。各命令的完整含义会在第 `09` 节展开。

## 直观理解

读 C++ 像看快递流转：类型是包装规格，变量是包裹，函数是中转站，引用是临时查看单，所有者负责最终签收与清理。先追踪包裹去了哪里，再研究每张单据的语法。
