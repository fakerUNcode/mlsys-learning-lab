**建议先完成 B01：环境、Tensor 基础和内存布局；然后进入 B02：梯度与训练循环。** 可按已有基础跳过已熟悉的材料。先通过小型 CPU 实验理解 Tensor → 梯度 → Attention → Decoder Block，再评估真实模型 baseline 所需的设备与资源。

- [全部任务清单](TASKS.md)：按 8 个阶段、批次顺序执行；每项有资料范围、产物和基本验收标准。
- [资料索引](REFERENCES.md)：官方文档、原论文与本地资料入口；任务中的 R 编号对应这里。
- [任务完成记录模板](COMPLETION_TEMPLATE.md)：每完成一项复制为 `completed/<任务ID>.md`，填写实际读过的资料范围、版本、命令、结果与独立验收。

## 如何分批推进

1. 同时只推进一个主批次，最多另加一个不依赖它的资料阅读任务。任务编号顺序是默认依赖顺序；GPU 环境阻塞时可先完成 CPU Tensor/梯度任务。
2. 每个任务拆成适合当前节奏的阅读、实现、验证和记录步骤；定期复盘并按实际完成量调整，不按日期自动勾选。
3. 每个任务优先拆为 1～3 次学习会话；超过三次仍未完成时，记录阻塞并拆子任务，子任务也写资料范围和验收标准。大型实现/实验允许跨多日，周数是预算。
4. 完成代码、验证、独立解释和证据记录后，才将清单中的 `[ ]` 改为 `[x]`。资料阅读型任务以自己的推导、对照表或讲解作为产物。
5. 遇到失败保留证据；标记“阻塞/待补验”，不能因代码由 AI 生成、目录存在或教程已看过而标完成。跳过条件任务要写“不适用及原因”，保留未勾选状态。
6. 同步更新 [每日记录](../daily-record/README.md)，用任务 ID 连接代码与报告。阶段验收未通过先补缺口，不开启下一阶段的大型集成。
