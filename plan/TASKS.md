# 全部剩余任务清单

L 表示本仓库内的学习与验证工作；P 表示需要独立模型级实现的扩展工作；L/P 表示两类工作都涉及。所有条目的“资料”编号见[参考资料索引](REFERENCES.md)。完成任务后，补[完成记录](COMPLETION_TEMPLATE.md)，记录资料范围、版本、证据和解释，再勾选。清单不意味着已有结果。

数值任务默认以 CPU float64 小输入建立 reference，float32 起步可用 `atol=1e-5, rtol=1e-4`；它们是初始容差，不是所有模型/dtype 的统一结论。记录最大误差，低精度与长序列另定容差并说明原因。性能任务不得要求预定加速倍数；正确性、可信计时和可解释证据才是基本验收。

- [ ] O04 服务调度专项（L，通常下一年）。触发：T84 选择服务方向。资料：R26 vLLM 官方入门/指标/调度；R21 服务 07～09；R19 第 11 章。验收：固定到达模式与并发做最小压测，区分排队/TTFT/TPOT/ITL/吞吐，记录尾延迟和 KV 压力；单请求推测实验不冒充服务结果。
- [ ] O05 分布式推理专项（L，通常下一年）。触发：单卡容量限制且有设备预算。资料：R26 PyTorch Distributed 进程组/collectives；R19 第 9 章。验收：最小多进程 collective 正确并测通信；模型切分实验另立任务，不能只跑 all-reduce 就声称分布式推理完成。
- [ ] O06 技术主题针对性补缺（L）。触发：实验或代码审查发现 ABI、Linux 性能工具、编译器或 CUDA 方面的知识缺口。资料：对应官方文档/课程具体章节，开始前写入记录。验收：每个缺口有一个独立小实现/诊断任务，明确退出标准；不把“学完所有 AI Infra”设为目标。
